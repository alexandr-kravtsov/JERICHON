# 🏗️ Архитектура системы JERICHON

Данный документ описывает архитектуру количественной торговой системы JERICHON. Архитектура построена в виде **моно-репозитория** с четким разделением ответственности (Separation of Concerns), что соответствует лучшим практикам разработки в hedge-фондах и требованиям академической строгости для воспроизводимости исследований.

## 🎯 Ключевые принципы

1. **Разделение кода и данных**: Папка `data/` содержит только артефакты (сырые и обработанные данные). Вся бизнес-логика, пайплайны и инжиниринг признаков вынесены в `src/`.
2. **Воспроизводимость (Reproducibility)**: Все гиперпараметры, пороги и настройки вынесены в `config/`. Исследования проводятся в `research/`, а переиспользуемый код инкапсулирован в `src/`.
3. **Безопасность исполнения**: Live-движок (`live/`) изолирован от веб-интерфейса (`app/`). Streamlit выступает только как монитор, а не как часть критического пути исполнения ордеров.
4. **Модульность стратегий**: Разные исследовательские направления (AFML, Nowcasting, Order Flow) изолированы в отдельные модули, но используют общие компоненты (провайдеры данных, бэктестер, риск-менеджмент).

## 📂 Структура проекта

```text
JERICHON/
├── config/                     # YAML-конфигурации (гиперпараметры, лимиты, настройки API)
├── data/                       # Хранилище данных (игнорируется в Git, кроме sample_data/)
│   ├── sample_data/            # ✅ В Git: минимальные срезы для unit-тестов и CI
│   ├── raw/                    # 🚫 Сырые тики, стаканы и свечи с MOEX AlgoPack
│   ├── interim/                # 🚫 Промежуточные данные (Dollar Bars, Super Candles)
│   └── processed/              # 🚫 Готовые датасеты (X, y) с фичами и лейблами для ML
├── src/                        # 🧠 ЯДРО: весь переиспользуемый Python-код
│   ├── pipeline/               # Бывший data/for_ml/: загрузка, очистка, лейблинг
│   ├── features/               # Инжиниринг признаков (микроструктура, режимы рынка)
│   ├── models/                 # Обучение, валидация (Purged CV), реестр моделей
│   ├── strategy/               # Логика торговых направлений (afml, order_flow, etc.)
│   ├── backtest/               # Движок реалистичного бэктестинга (комиссии, проскальзывание)
│   ├── risk/                   # Управление капиталом (Ralph Vince optimal f, sizing)
│   └── utils/                  # Логирование, визуализация, хелперы
├── research/                   # 🔬 Jupyter Notebooks только для экспериментов и EDA
│   ├── afml/                   # Эксперименты с Triple Barrier, CUSUM, Feature Importance
│   ├── nowcasting/             # Прогнозирование экстремумов
│   ├── super_candles/          # Анализ статистик Super Candles (tradestats, obstats)
│   └── order_flow/             # 🚀 Основной фокус: прототипирование стратегий на потоке ордеров
├── live/                       # ⚡ Продакшн-модуль лайв-торговли
│   ├── engine.py               # Главный асинхронный цикл опроса и исполнения (бывш. live_engine.py)
│   ├── bcs_executor.py         # Клиент для отправки ордеров в BCS API
│   └── reconciliation.py       # Сверка локальных позиций с брокером
├── app/                        # 🖥️ Streamlit веб-приложение (только мониторинг и управление)
│   ├── dashboard.py
│   └── pages/
├── tests/                      # 🛡️ Unit и интеграционные тесты (критично для надежности)
├── docs/                       # 📚 Документация (включая этот файл)
├── models/                     # Артефакты обученных моделей (.pkl, .json) или ссылки DVC
├── .env.example                # Шаблон переменных окружения (ALGOPACK_TOKEN, BCS_REFRESH_TOKEN)
├── pyproject.toml              # Управление зависимостями и настройками проекта
└── README.md                   # Главное описание проекта
